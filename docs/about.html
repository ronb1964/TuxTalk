About TuxTalk

Who makes it, how it's made, and why the code matters to me as much as the app does.

Who I am

I'm Ron Brand. I build custom camper vans for a living, and before that I spent 30 years as a fiber optic splicing technician. I'm not a programmer, and I can't read code.

I wanted to talk to my computer instead of typing, on Linux, without my voice going off to somebody's server. TuxTalk is what came out of that. These days I dictate almost everything I write with it, including the messages I send while I'm working on TuxTalk.

How it's made

TuxTalk is written by Claude, Anthropic's AI, and every commit says so. My part is deciding what it should do, testing every change on real machines, and living with the result every day. When something's off, I'm usually the first one to trip over it.

Keeping the code clean

I know what a lot of people think of AI-written apps, and plenty of the time they've earned it. I don't want TuxTalk to be one of those. Keeping the code clean matters to me as much as the app working, so there's a written checklist every change has to meet before it goes in. Nothing left lying around that isn't used. No two pieces of code doing the same job. Comments that explain why something is there, and tests that check what a user would actually notice.

The goal is that an experienced developer can open any file and think it's well put together, not just that it happens to work. If you look and it isn't, I want to know.

Don't just take my word for it

  • Over 3,700 automated tests run on GitHub every time the code changes.
  • Before a release I test it in virtual machines on Ubuntu, Linux Mint, Fedora Silverblue, Fedora KDE, Zorin, Pop!_OS, openSUSE Tumbleweed and Debian, plus Nobara, which I use every day.
  • The hotkey helper, the one part that reads the keyboard, went through three security reviews. The last one was by guelz, another developer, in the open, and guelz went on to contribute Type at pause.
  • Everything is public: every change, every bug report, and how it got fixed.

Get in touch

Found a bug, or have an idea? Open an issue or start a discussion on GitHub. I'm on Mastodon too, as @ronb1964@mastodon.social. I read everything.
